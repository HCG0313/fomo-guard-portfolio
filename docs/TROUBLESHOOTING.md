# Troubleshooting

이 문서는 개발 중 겪은 문제와 해결 과정을 정리한 기록입니다.

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 수익률만으로 FOMO 설명이 어려움 | 수익률은 결과일 뿐 포트폴리오 형성 과정을 설명하지 못함 | 매수일, 최근 수익률, 비중 변화율을 함께 보는 진단으로 전환 |
| CSV 데이터가 부족할 수 있음 | 사용자가 모든 정밀 진단 컬럼을 넣지 않을 수 있음 | `timeline_based`, `snapshot_estimated`, `insufficient_data` 상태로 분리 |
| 투자 추천처럼 보일 위험 | 금융 대시보드 문구가 매수/매도 권유처럼 읽힐 수 있음 | 점검형 표현만 사용하고 금지 표현을 규칙화 |
| 외부 API 사용 시 데모 불안정 | API 키, 인증, 네트워크 문제 가능 | 정적 웹앱과 샘플 CSV 중심으로 구현 |
| 규칙 문서와 점수 산식 불일치 가능성 | 구현 중 산식 항목이 바뀔 수 있음 | 최종 점검에서 FOMO 점수 항목을 규칙서 기준으로 맞춤 |
| favicon 404 | 브라우저가 기본 favicon을 요청 | data URL favicon 추가 |
| 샘플과 CSV 결과가 달라짐 | 앱에 `2026-05-04`를 고정하고 업로드 데이터의 기준일을 받지 않음 | 샘플 CSV에 `analysis_date`를 넣고 행 전체에서 기준일 일치 여부를 검증. 샘플 미리보기와 CSV 업로드가 같은 날짜로 계산되도록 수정 |
| 잘못된 가격·날짜로 점수 왜곡 | 매수가 0이면 수익률 계산이 무한대가 되고 존재하지 않는 날짜도 입력될 수 있음 | 가격·수량의 범위와 ISO 날짜를 검사하고 기준일 이후 매수일을 거부 |
| 공개 PDF에 개인 PC 경로 노출 | 브라우저에서 PDF로 인쇄할 때 로컬 `file:///` 경로가 꼬리말에 포함됨 | PDF 원본의 해당 꼬리말을 실제 텍스트 객체에서 삭제하고 메타데이터를 비운 공개본 제작. 기존 기록은 비공개 보관 |

## 대표 해결 사례

### 샘플 분석의 기준일을 데이터와 함께 보관

초기 데모는 2026년 5월 4일을 앱 전체 기준일로 고정했습니다. 이 방식은 시간이 지나도 샘플 화면을 유지하지만, 다른 CSV를 올려도 같은 과거 날짜로 최근 편입 여부를 계산하는 문제가 있었습니다. 현재는 샘플 CSV의 `analysis_date`를 읽고, 일반 CSV에 이 열이 없으면 실행 당일을 기준으로 계산합니다. 화면에 기준일을 표시해 결과의 시간 범위를 확인할 수 있습니다. 샘플 시장 지표는 실시간 수치가 아닌 시연용 예시로 표시합니다.

검증: 샘플 CSV를 파싱해 FOMO 점수가 정상적인 유한값(10/12)으로 계산되는지, 잘못된 날짜·매수가 0·HTML 태그 입력이 거부 또는 이스케이프되는지 확인했습니다.

### FOMO를 수익률이 아니라 흐름으로 판단

처음에는 수익률과 비중만으로 FOMO 위험을 판단하려 했지만, 같은 비중도 장기 보유와 후행 편입은 의미가 달랐습니다. 그래서 `purchase_date`, `recent_7d_return`, `recent_30d_return`, `weight_change_7d`를 함께 사용하는 방식으로 바꿨습니다.

### 추천이 아닌 점검 서비스로 문구 수정

진단 결과가 투자 조언으로 오해되지 않도록 매수/매도 표현을 제거했습니다. 인사이트는 "가능성이 있습니다", "점검이 필요합니다", "확인해보는 것이 좋습니다" 같은 표현으로 제한했습니다.
